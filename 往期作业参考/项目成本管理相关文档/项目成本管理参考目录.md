### 1．合同签订前的成本估算 ★

- 【采用的估算方法】——案例用**类比估算**：根据以往类似项目的经验进行粗略的估算。
  （`快递代取` 用的是**功能点估算法**）
- 【技术栈与历史经验】——案例原句是"根据用户的要求，系统采用 B/S 结构，公司的 JSP+SQL Server
  技术比较成熟，以前成功完成过类似项目"。
  > ⚠️ **改写提示**：技术栈**不要展开**（《项目介绍》2.2 已写），
  > 这里只需一句"本项目为课程实训小组项目，采用前后端分离的 B/S 架构，
  > 组内成员具备 Python 与 Vue 开发经验"，然后直接进入估算。
- 【依据 SOW / 需求设计说明书】——本项目依《需求规格说明书》确定的功能范围（F1~F9 九类功能）
- 【估算出的三个数】：需要 X~X 个开发人员，X 个月左右的开发时间，大约 X~X 人月的工作量
- 【合同参考报价】

> **案例的数字**：2~3 个开发人员、2 个月、4~6 人月 → **10 万~15 万**参考报价。
> **往期学生的数字**：社团管理系统 2k~3k；诗词学习通 1000 元；好好学习 2~3 万。
>
> 🔴 **对你们特别重要**：`诗词学习通` 在这段加了一句很关键的话——
> "由于考虑到我们学生自己开发，所以 1000 可以作为合同的参考报价。"
> **你们是课程实训项目、没有真实合同、而且用的是自有笔记本和免费开源数据集**，
> 所以报价必然远低于案例。**一定要说明为什么低**（学生自研、无商业交付、
> 设备自有、数据与模型开源），否则数字和案例差太多会显得突兀。
>
> 建议写法："本项目为课程实训项目，不涉及商业合同。参照类比估算方法，
> 按 4 人 × 10 周的实际投入测算，仅计入直接人力与耗材成本，参考报价约为 X 元。"

### 2．合同签订后成本估算 ★

**过渡段（案例原文，照抄）**：
> 合同签订后，根据现有的资源和 WBS 分解的结果，进一步细化估算。由于 WBS 分解是针对项目的功能进行的分解，
> 在成本估算的时候，首先估算每个任务的开发工作量，然后通过系数获得相应的质量、管理任务的工作量，
> 从而计算直接成本，之后计算间接成本以及总成本。具体过程如下：

#### （1）资源估算 ★
案例分两类列：

**人力资源：**
- 【4 个项目成员】——案例写的是"X 个开发人员、1 个项目管理人员（项目经理）、
  1 个质量保证人员、1 个配置管理人员"
  > 你们是 4 人小团队，**一人多角色**，建议写成：
  > "项目组共 4 人，其中项目经理兼技术负责人 1 人、前端与文档负责人 1 人、
  > 需求与质量负责人 1 人、配置与工具负责人 1 人。"
  > （角色名称与《项目介绍》3.1/3.2 保持一致）

**设备资源（作为间接成本计算）：**
- 【如：4 台开发笔记本，其中 1 台配备 RTX 4050 6GB 显卡用于模型训练】
- 【如：1 台安卓手机（用于推流测试）】
- 【如：云服务/API 调用费用，若有】

> ⚠️ **只列规格与用途，不展开技术介绍**（那是《项目介绍》2.1 的事）。
> 💡 你们有一个可以写实的点：**智能体复核用到视觉语言模型（VLM）**，
> 如果调用云端 API 会产生费用，这是一项真实的间接成本；若用本地量化模型则写"本地部署，无额外费用"。
> 无论哪种，写出来都比案例的"3 台电脑、1 台服务器"更贴合实际。

#### （2）项目成本估算 ★ —— 这里是全文主干，共 7 步

**步骤1：根据项目任务分解结果 WBS 估算出项目开发工作量**

**表1：项目开发工作量估算表　　单位：人天**（案例的列）

| WBS 编号 | 任务名称 | 估计值 | 小计 |
|---|---|---|---|

> 🔑 **填写要点**：
> - **WBS 编号与任务名称直接照抄《工作任务分解说明书》表2-1~表2-6**
> - **估计值 = 该工作包的工期 × 参与人数**（把"工期（天）"换算成"人天"）
>   例：`2.1 视频源接入` 工期 5 天，责任人 2 人 → 估计值 10 人天
> - 一级任务行写小计（案例的写法：`1 通用功能-增量1 …… 31`），下列子任务
> - 对无法自研的部分，案例直接在"任务名称"里标注：`教师备课系统 外包5000元`、
>   `网上考试 外购3000元`、`论坛 已存在`
>   > 【你们的对应情况】：所用数据集（VOC2020 等）与开源模型（D-Fire、Pyronear）
>   > 可写为"开源免费，成本 0 元"；GPU 算力为自有设备，计为间接成本

**步骤2：计算开发成本**
```
(a) 从表1得知项目工作量是 X 人天，假设开发人员成本参数 = Y 元/人天
    则内部开发成本 = Y 元/天 × X 天 = Z 元。
(b) 加上外包外购部分的软件成本 A 元，
    则开发成本 = Z + A = B 元。
```
【换成你们的人天数和成本参数】

> 💡 **成本参数的选取要合理**：案例用 480 元/人天（企业口径）。
> 你们是学生项目，往期有 500、600、300、10 元/人天各种写法。
> **建议给一个说得过去的低值并说明理由**，或者用"折算工时成本"的说法。

**步骤3：计算管理、质量成本**
```
由于任务分解的结果主要是针对开发任务的分解，管理任务和质量任务成本可以通过计算开发任务成本得到，
因此根据以往的经验，管理任务和质量任务成本 = 开发任务成本 × 20% = X 元。
```
【系数 20% 可沿用或说明你们的取值依据】

**步骤4：计算直接成本**
```
直接成本 = 开发成本 + 管理和质量成本 = X 元。
```

**步骤5：计算间接成本**
```
(a) 间接成本包括前期合同费用、房租水电、培训、员工福利、客户服务等。
(b) 根据以往经验，采用公式：间接成本 = 直接成本 × 25% = X 元。
```
> ⚠️ **案例这个间接成本口径是企业的**（房租水电、员工福利、客户服务），
> 学生项目**这些都没有**。改写建议：
> "本项目的间接成本主要为设备折旧与电力消耗、数据集获取与存储、
> 云端推理 API 调用（若有）等。由于开发设备为组员自有、场地由学校提供，
> 间接成本按直接成本的 X% 估算。"

**步骤6：计算总估算成本**
```
项目总估算成本 = 直接成本 + 间接成本 = X 元。
```

**步骤7：重新评估项目的报价**
```
重新评估一下项目报价的准确性，当然这时候，项目的合同已经签署了，
报价是不能更改的，但是通过再次的评估可以进一步明确企业的项目运作和利润情况等。
如果项目的风险利润是 30%，其中风险基金 10%，利润 15%，税费 5%。
则项目的总报价 = X × 1.3 = Y 元。
```

**另：简便算法（案例在步骤7后附了一段，建议保留）**
```
另外，可以采用简便的算法进行估算，企业的报价可以通过开发规模的估算直接得出，
例如如果成本系数为 2.5 万元/人月，项目规模 X 人天，一个人月 22 人天，
则项目报价 = 25000 × X / 22 = Y 元。
```

> 🎯 **案例最漂亮的一笔**：两个算法算出 117858 和 117045，用"两种算法互相印证"收尾。
> 你们也这样做，**两个数接近就说明估算可信**。
