# FireGuard AI 多智能体协同检测架构

- 日期：2026-10-21
- 目标：让“智能体提高准确率、增强远景识别”在系统界面与告警证据中可见、可解释、可评测。

## 1. 设计原则

本项目的“多智能体”不是多个大模型互相聊天，而是把检测链路拆成职责单一、输出可解释的 Agent：

- 每个 Agent 只做一件事；
- 每个 Agent 都输出结构化证据；
- 主链路完全本地运行，不依赖云端 API；
- VLM 只作为后续可选增强，不阻塞演示。

## 2. 五个 Agent

| Agent | 输入 | 输出 | 作用 |
| --- | --- | --- | --- |
| 感知 Agent | 当前帧 | fire/smoke 框、置信度 | 整图双类检测 |
| 远场 Agent | 当前帧、扫描间隔 | 切片检测框、跨片 NMS 结果 | 提升远处小目标召回 |
| 时序 Agent | 连续帧检测结果 | 烟雾连续帧计数、切片结果保持 | 抑制单帧抖动、避免漏检断档 |
| 复核 Agent | 告警区域裁剪图 | 通过/拦截、局部置信度 | 二次检测，压低误报 |
| 决策 Agent | 各 Agent 证据、阈值 | 状态、风险分、告警 | 分级、冷却、告警合并 |

## 3. 数据流

```text
视频帧
  ↓
感知 Agent（整图 YOLO）
  ↓
远场 Agent（每 2 秒切片扫描 + 跨片 NMS）
  ↓
时序 Agent（切片结果保持 + 烟雾连续帧）
  ↓
复核 Agent（告警局部裁剪放大后复检）
  ↓
决策 Agent（风险分级、冷却、告警合并）
  ↓
WebSocket detection / alarm 事件（携带 agents trace）
```

## 4. Agent Trace

每一帧检测和每条告警都会携带 `agents` 字段，例如：

```json
{
  "perception": {"objects": 6, "top_confidence": 0.798},
  "farfield": {"active": true, "tile_size": 640, "interval": 2, "held": 3},
  "temporal": {"smoke_streak": 2, "required": 3, "cooldown": 8},
  "verification": {"active": true, "triggered": true, "passed": true, "confidence": 0.656},
  "decision": {"status": "critical", "risk": 90, "alarm": true}
}
```

## 5. 界面体现

| 界面 | 展示内容 |
| --- | --- |
| 左侧「智能体协同」 | 五个 Agent 卡片、实时状态、最新决策轨迹、最近轨迹、评测指标 |
| 实时监控顶部 | “智能体链路”状态条：感知 / 远场 / 时序 / 复核 / 决策 |
| 告警中心 | “智能体”列显示 `已复核`，表示该告警通过局部复核 Agent |
| 总览页 | 模型 `smoke + fire`、远距离模式、告警复核开关 |

## 6. 为什么不上 LLM 多智能体框架

- 6GB 显存同时跑检测和本地 VLM，延迟与显存风险高；
- 明天演示需要稳定、离线可跑；
- 规则驱动的 Agent 每个决策都能解释和评测，比“黑盒对话”更适合课程答辩。

后续若接入 VLM，可把它作为“灰区复核 Agent”：仅当本地复核置信度处于 0.15~0.25 时调用，失败自动回退到本地决策。

## 7. 支撑指标

| 指标 | 结果 |
| --- | --- |
| 官方 test mAP50 | 0.724 |
| 远景小目标召回 | 81.2%（旧模型 18.5%） |
| 整图 → 切片召回 | 94.0% → 96.0% |
| 困难负样本图级误报 | 52.7% → 34.2% |
| 校准后 fire 误报 | 4.8% |
| SmokeFire 烟雾召回 | 90.8% |
