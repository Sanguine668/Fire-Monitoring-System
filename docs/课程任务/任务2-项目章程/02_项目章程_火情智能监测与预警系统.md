## 项目目的与立项理由

火灾早期发现直接影响损失规模。传统烟感设备受安装位置限制，难以覆盖大空间与室外场景；现有开源烟火检测项目多以实验室近景演示为主，存在数据重复、分辨率低、远距离样本少、误报率高等问题。

本项目作为软件项目管理课程小组实训项目，目标是在 8 周内构建一套可运行、可演示、过程可追溯的视频火情监测与预警系统，并按要求加入智能体复核与远距离识别能力，形成相对现有方案的优势。

立项理由：

1. 完成课程要求的"需求 → 设计 → 开发 → 测试 → 结项"完整项目管理过程；
2. 通过真实项目训练小组的需求分析、进度控制与风险管理能力；
3. 成果可作为课程展示作品，具备继续迭代与参加竞赛的基础。

## 项目目标

1. 实现"视频源 → AI 烟火检测 → 分级预警 → 前端展示 → 历史留存"的完整业务闭环；
2. 支持安卓手机摄像头在局域网/热点环境下实时推流识别，并支持本地上传视频作为保底演示通道；
3. 完成自训练 YOLO 模型的训练、评测与误差分析，并与公开模型进行量化对比；
4. 按老师新增要求实现智能体复核（降低误报）与远距离识别（远景小目标）能力；
5. 交付可运行的演示系统与完整的课程文档（软件介绍、项目章程、需求规格说明书、工作任务分解说明书）。

## 方法

1. **敏捷迭代**：以周为迭代周期，每周产出可演示增量，核心闭环优先；
2. **例会与看板**：每周实训固定站会，任务状态在看板维护，会议纪要及时归档；
3. **版本与配置管理**：Git 分支 + Pull Request 提交，提交信息统一格式，禁止提交数据与模型权重；
4. **文档驱动**：按课程模板产出文档，走"起草 v0.1 → 评审 v0.5 → 定稿 v1.0"流程，评审留痕；
5. **量化验证**：模型训练与对比使用统一验证集与演示素材，指标与实验记录入库；
6. **风险与演示保障**：维护风险台账，演示采用"手机推流 + 上传视频"双通道，演示前全链路预演。

## 简要范围说明书

**范围内（本期交付）**

1. 实时监控：多路视频画面、检测框、FPS/延迟/风险分；
2. 烟火检测：自训练 YOLO 模型的 fire/smoke 检测；
3. 分级预警：连续帧确认 + 置信度阈值 + 告警冷却，输出黄色预警与红色明火告警；
4. 视频源管理：本地上传视频（循环播放）、手机 IP Webcam 推流、RTSP 摄像头接入与启停；
5. 历史告警与统计分析：告警记录、确认处理、趋势图表；
6. 系统配置：阈值、连续帧、冷却时间等参数可在线调整；
7. 智能体复核与远距离识别（老师新增要求）：方案设计、开发与远景测试集评估。

**范围外**

1. 不开发移动端 App（手机仅作为视频源）；
2. 不做云端多租户部署与容器化交付（列为演进方向）；
3. 不做消防设备联动控制；
4. 不使用真实火源进行演示。

## 主要风险与假设

| 风险 / 假设 | 影响 | 应对 |
| --- | --- | --- |
| 数据集重复、远景样本少 | 模型指标虚高，远距离效果不足 | 先清洗去重再重划分；定向补充烟类与远景数据 |
| 智能体依赖外部模型或网络 | 复核不可用 | 本地小模型优先，云端可选，失败回退本地规则 |
| 每周有效时间有限（约 3.5 小时） | 进度延迟 | 核心闭环优先，每周可演示，后置功能及时降级 |
| 演示现场网络不可控 | 手机推流失败 | 使用手机热点；准备上传视频保底通道并提前预演 |
