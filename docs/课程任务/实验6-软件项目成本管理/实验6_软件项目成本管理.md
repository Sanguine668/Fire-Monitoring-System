## 一、开篇总述

成本计划是项目预算的组成部分，它规定计划期内完成项目所需的成本水平以及为此采取的主要措施，属于**成本的事前管理**；其核心作用是通过对成本的计划与控制，分析实际成本与计划成本之间的差异。

《火情智能监测与预警系统》的成本估算过程是**循序渐进**的：随着项目的不断发展，估算可以重复多次进行，而且是逐步求精的。具体过程如下：启动前用类比法做一次粗估，确定参考报价区间；启动后依据 WBS 与资源费率做自下而上的细化估算，形成成本预算；执行中按周跟踪实际成本，最后用挣值分析对比基准与实际。

### 1.1 成本口径

课程项目没有真实工资支出，必须先把口径定义清楚，否则金额没有意义。

**（1）人工费率。** 按当地大学生实习日薪折算：

```
费率 = 160 元/天（实习日薪） ÷ 8 小时 = 20 元/工时
```

换算成人天单价为 **160 元/人天**。在资源工作表中把 4 名成员的标准费率统一设为 20 元/工时。

> 选择实习日薪而不是最低工资标准，是因为本项目投入的是**软件开发劳动**，按专业实习的市场价折算比按最低工资折算更贴近实际；同时 160 元/天对学生项目来说仍属于保守取值（不包含社保、管理费等企业附加成本）。

**（2）工时折算。** 项目每周只有一次实训课（3.5 小时），其余为课外投入，因此把资源的**分配单位设为 25%**，即每人每个工作日投入 2 小时（每周约 10 小时）。Project 按「工时 = 工期 × 8 小时 × 分配单位」自动计算工时，工时与金额通过费率绑定。

**（3）成本构成。** 项目未发生任何真实采购支出，全部成本为人工成本：

| 成本项 | 计划 | 实际 |
| --- | --- | --- |
| 人工成本 | Σ(计划工时 × 20 元/工时) | Σ(实际工时 × 20 元/工时) |
| 设备成本 | 自有笔记本，不计折旧（0 元） | 0 元 |
| 其他支出 | 未发生 | 0 元（打印装订尚未产生） |

## 二、项目启动前的成本估算

**（1）采用的估算方法。** 采用**类比估算法**：根据以往同类课程实训项目的经验，按"人数 × 周期 × 人均投入"做粗略估算。项目组没有历史商业项目数据，因此类比对象为本组此前完成的前后端分离课程项目。

**（2）技术栈与经验。** 本项目为课程实训小组项目，采用前后端分离的 B/S 架构，组内成员具备 Python 与 Vue 开发经验（技术栈详见《项目介绍》，此处不展开）。

**（3）估算依据。** 依《需求规格说明书》确定的功能范围（UC-01 ~ UC-16，覆盖实时监控、烟火检测、分级预警、视频源管理、历史告警、统计分析、系统配置、智能体复核、远距离识别）与《工作任务分解说明书》的阶段划分。

**（4）估算出的三个数。**

| 估算项 | 估算值 |
| --- | --- |
| 开发人员 | 4 人（组长兼技术负责人、前端与文档、需求与质量、配置与工具） |
| 开发周期 | 约 2 个月（2026-09-03 ~ 11-05，共 9 周） |
| 工作量 | 约 **2.1 人月**（4 人 × 9 周 × 约 10 小时/周 = 360 人时 ≈ 45 人天 ≈ 2 人月） |

**（5）参考报价。**

本项目为课程实训项目，**不涉及商业合同**。参照类比估算方法，按 4 人 × 9 周的实际投入、以 160 元/人天折算，参考报价约为 **7,100 ~ 7,800 元**。

> **为什么这个数字远低于常见案例**（案例的参考报价通常是几万到十几万元）：本组是学生自研，不存在商业交付与售后责任；开发设备为组员自有笔记本，场地由学校提供；数据集与基线模型均为开源免费。因此报价只包含折算后的直接人力成本。

**步骤 2：计算开发成本**

```
(a) 从表 3-1 得知项目工作量是 46.75 人天，开发人员成本参数 = 160 元/人天
    则内部开发成本 = 160 元/天 × 46.75 天 = 7,480 元。
(b) 加上外包外购部分的软件成本 0 元，
    则开发成本 = 7,480 + 0 = 7,480 元。
```

**步骤 3：计算管理、质量成本**

案例的做法是按"开发任务成本 × 20%"计提管理与质量成本。**本项目不适用这一算法**：WBS 中已经单列了管理与质量类任务（项目章程、需求评审、功能测试、缺陷修复、误报测试、结项归档），它们的成本已包含在上面的 46.75 人天内，若再按系数计提会重复计算。

因此：**管理、质量成本 = 0 元（已包含在开发成本中）**。

**步骤 4：计算直接成本**

```
直接成本 = 开发成本 + 管理和质量成本 = 7,480 + 0 = 7,480 元。
```

**步骤 5：计算间接成本**

案例的间接成本口径是企业口径（房租水电、员工福利、客户服务），本项目不适用。本项目的间接成本主要是**电力消耗与数据存储**：设备为组员自有、场地由学校提供、数据集开源免费、视觉模型本地部署无 API 费用。按以往经验，间接成本约为直接成本的 5%：

```
间接成本 = 7,480 × 5% = 374 元。
```

**步骤 6：计算总估算成本**

```
项目总估算成本 = 直接成本 + 间接成本 = 7,480 + 374 = 7,854 元。
```

**步骤 7：重新评估项目的报价**

课程实训项目没有商业合同，报价不可更改的问题不存在，但为完整起见按企业口径试算一次：若考虑风险基金 10%、利润 15%、税费 5%，合计 30%：

```
参考报价 = 7,854 × 1.3 ≈ 10,210 元。
```

**简便算法（互相印证）**

```
项目报价 = 成本系数 × 项目规模
若成本系数取 3,500 元/人月，一个人月按 22 人天计，
则规模 = 46.75 ÷ 22 ≈ 2.13 人月，
项目报价 = 3,500 × 2.13 ≈ 7,455 元。
```

两种算法分别得到 **7,480 元**（自下而上）与 **7,455 元**（系数法），相差仅 0.3%，**互相印证，说明本次估算可信**。

### 4.5 分任务成本差异与原因

**（1）超支集中在"启动与文档"类任务，四项合计 1,040 元。**

项目立项与章程超支 320 元、环境准备 240 元、参考资料整理 240 元、需求调查 240 元。这些任务的计划工期都只有 2 ~ 3 天，实际却横跨 4 ~ 8 天。它们不是"干得慢"，而是**断续等待**——等课程模板下发、等训练环境装好、等组内评审意见。日历时间被拉长，工时随之上升。

**（2）技术实现类任务基本控制在预算内。**

前端开发与计划完全一致（240 元），系统设计反而节约 40 元，后端检测闭环与前后端联调各超支 80 元（约 20%）。这说明按"每人每天 2 小时"估算技术类任务的投入是可行的。

**（3）最大的"节约"其实是估算错误。**

数据集获取与质量体检（任务 14）中期成本比基准低 720 元，看起来是大额节约，实际原因是它作为**自动计划任务**，基准工期被前置任务连带拉长到 09-07 ~ 09-22（12 个工作日），造成预算虚高；实际只用了 5 个工作日。保存成本基准之前必须逐项复核自动计划任务的工期。

**（4）估算方法的复盘。**

自下而上估算（7,480 元）与系数简便算法（7,455 元）相差仅 0.3%，说明**总量估算是准的**；但偏差全部落在结构上——总盘子没超，任务之间却在互相挪移。对预算的检验不能只看总额，必须逐任务核对。

**（5）总体结论。**

项目在状态日期上"进度略快、成本超支"：SV +76 元、SPI 1.02，CV −480 元、CPI 0.89。超支与节约相互抵消后仍净超支 480 元，占总预算的 6.4%。**计划对"需要等待外部输入"的任务普遍估计不足**，这类任务的工期应当按日历跨度而不是有效工时来估算。

## 五、成本控制措施

1. **按周跟踪实际工时**：每周实训课后由各成员报当周实际投入工时，录入 Project 后核对成本曲线；
2. **设偏差预警线**：单个任务的成本偏差超过其预算的 20%，或 CV 为负且绝对值超过 300 元时，在周会上提出并分析原因；
3. **等待型任务单独预留缓冲**：需要等外部输入（课程模板、软件安装、评审意见）的任务，工期按日历跨度估算并预留 1 ~ 2 天，避免执行期被动超支；
4. **保存基准前复核自动计划任务**：自动计划任务的工期会随依赖关系放大，保存成本基准前逐项复核其工期与工时；
5. **人力均衡控制**：用资源工作表检查各成员工作量，偏差超过 30% 时重新分配任务；
6. **变更留痕**：任何导致预算变化的调整都通过 Git 提交记录留痕，并在中期计划中重新固化。

针对上述 4.5 发现的五个问题，成本和资源优化方案如下：

| 问题 | 优化措施 | 预期效果 |
| --- | --- | --- |
| 等待型任务估期偏短导致超支 | 把项目章程、环境准备、需求调查的工期由 2 ~ 3 天调整为 4 ~ 5 天，工时按实际等待周期分配 | 基准更接近真实，减少执行期被动超支 |
| 自动计划任务预算虚高 | 任务 14 的工期与工时重新按 3 个工作日估算，计划成本由 960 元降为 240 元 | 总预算下调 720 元，消除虚高 |
| 组长工作量过于集中 | 系统设计文档改为四人共同承担；接口联调交李汶航；功能测试交欧阳宇康；演示预演由李汶航主导 | 人力均衡，降低单点风险 |
| 数据治理滞后将推高后期成本 | 把前期技术任务提前完成释放出的工时投入数据清洗与数据补充（任务 17 由 3 人增至 4 人） | 避免后期为追赶进度付出更高代价 |
| 管理与质量成本口径不清 | 明确本项目 WBS 已含管理质量任务、不另按系数计提，间接成本按直接成本 5% 计 | 消除重复计算，估算口径可复现 |

优化后重新查看成本表，确认总预算仍控制在 7,480 元以内，并将调整结果保存为新的比较基准。
