## 三、三条容易漏、但能明显拉开差距的点

**1. 配置项清单要覆盖四类，包括"不入库"的那些。**

代码、文档、数据、模型权重都属于配置项。但模型权重（`best.pt`）和数据集体积大、有许可限制，**不进 Git**——这并不意味着它们不是配置项，而是**存储方式不同**。在清单里要登记它们，并在备注里写明"存放于本地 `ai/runs/`、不入库的原因、备份方式、责任人"。

这一条最能体现"理解配置管理"，因为配置管理管的是"配置项的完整性"，不是"Git 使用说明"。

**2. 权限表用真实角色，并能截图佐证。**

不要写"管理员/开发人员"这种泛称，直接写 GitHub 的真实角色（Owner / Maintainer / Developer），并截图仓库的 Collaborators 与分支保护设置。参考目录里明确写了这个写法。

**3. 给出"可核验路径"。**

在文档里写明：仓库地址、分支命名规则、各类配置项所在目录。让老师能自己进仓库按图索骥查到——**能被独立核验的库，才算真的建起来了**。
