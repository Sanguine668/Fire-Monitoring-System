## 1. 项目介绍

### 1.1 项目背景

火灾具有突发性强、危害大的特点，早期发现并预警是降低损失的关键。现有开源烟火检测项目多以实验室近景演示为主，存在数据重复、分辨率低、远距离样本少、误报率高等问题。本项目围绕"视频火情智能监测与预警"构建一套可演示、可迭代的系统：接入手机摄像头、本地上传视频与网络摄像头，实时识别火焰与烟雾，产生分级预警，并支持历史告警与统计分析。

### 1.2 项目目标

- 实现"视频源 → AI 烟火检测 → 分级预警 → 前端展示 → 历史留存"的完整业务闭环；
- 支持**安卓手机摄像头实时推流识别**，在局域网/手机热点环境完成实时检测与展示（老师重点要求）；
- 支持**本地上传视频**作为循环视频源，保证课堂演示可控、可复现；
- 按老师新增要求，加入**智能体复核**与**远距离识别**能力，形成相对现有方案的优势；
- 在约 8 周（每周约 3.5 小时实训）内交付可运行系统与完整的项目管理文档。

### 1.4 演示约束与验收口径

- 课堂不允许使用真实火源，演示素材为公开烟火视频、屏幕播放/翻拍素材与本地视频文件；
- 基础验收：手机画面与上传视频能被实时识别，告警闭环完整、画面与告警同步；
- 增强验收：远景测试集上小目标召回率提升、疑似误报（云/雾/夕阳/灯光/蒸汽）减少；
- 系统运行在小组自有 Windows 笔记本上，通过手机热点 + 局域网连接，规避校园网限制。

### 1.5 数据与模型现状（重要）

**数据集（gengyanlei 烟火数据集 VOC2020）**

| 项目 | 结果 | 影响 |
| --- | --- | --- |
| 样本规模 | 2059 张图 / 3299 个标注框 / 仅 fire 一类 | 缺 smoke 标注，烟类检测依赖公开模型兜底 |
| 重复情况 | 精确重复 57 组（冗余 59 张）；近重复 149 组（冗余 184 张） | 可能导致训练/验证集泄漏，指标虚高 |
| 分辨率 | 宽度中位数 500 像素，67% 图片宽 < 640 | 难以支撑远距离小目标 |
| 目标大小 | 小目标（<32×32）占 14.7%，中位框面积 8241 像素² | 近景/中景为主，远景样本稀缺 |
| 画面质量 | 模糊图 79 张、过暗图 119 张 | 存在噪声样本，需要清洗 |

**模型（首轮自训练）**

| 项目 | 结果 |
| --- | --- |
| 模型与环境 | YOLO26n（Ultralytics，2.5M 参数），PyTorch 2.11.0+cu128，RTX 4050 6GB |
| 数据划分 | train 1750 / val 309（随机 85/15，存在重复泄漏风险） |
| 验证指标 | mAP50 = 0.758，mAP50-95 = 0.424，Precision = 0.759，Recall = 0.699 |
| 置信度特点 | 整体偏低（部分图最高仅 0.07，少数可达 0.8+），告警阈值取 0.1 |
| 端到端验证 | 上传演示视频 25 秒内产生 4 条严重明火告警，MJPEG 画面正常 |
| 下一步 | 去重 + 按相似组重划分出"诚实基线"，补充 smoke 与远距离数据后重训 |

## 2. 技术方案

### 2.1 技术栈

| 层 | 技术选型 | 说明 |
| --- | --- | --- |
| 前端 | Vue3 + Vite + Element Plus + ECharts | 五个页面，已接入真实接口与 WebSocket |
| 后端 | FastAPI + WebSocket + SQLite | REST 接口、实时事件、告警落库与统计 |
| 视频接入 | OpenCV + MJPEG；手机 IP Webcam、上传 MP4、RTSP | 统一抽象为 file / rtsp / http 三类源 |
| AI 检测 | Python + Ultralytics YOLO26n（自训练）+ CUDA | 已在 RTX 4050 上完成首轮训练与评测 |
| 智能体（规划） | 多尺度切片 + 时序融合 + 视觉语言模型复核 | 一级本地检测保实时，二级复核降误报 |
| 部署 | 单台 Windows 笔记本，局域网/手机热点 | 课堂一键启动，上传视频作为保底通道 |

### 2.2 整体流程

```text
安卓手机摄像头（IP Webcam 推流）─┐
本地上传/内置 MP4（循环播放） ───┼─→ 视频源统一抽象（file / rtsp / http）
RTSP 网络摄像头 ─────────────────┘
                                 ↓
                     OpenCV 读取视频流（3~5 FPS 抽帧）
                                 ↓
                      YOLO 烟火检测（fire / smoke）
                                 ↓
         告警规则引擎：连续帧 + 置信度阈值 + 冷却时间 + 风险分
                                 ↓
          智能体复核（规划）：低置信/高风险样本二次视觉判断
                                 ↓
                    FastAPI：告警落库（SQLite）
                                 ↓
                     WebSocket 实时推送前端
                                 ↓
         前端：实时画面 + 检测框 + 告警弹窗/声音
                                 ↓
              历史告警查询 / 统计图表 / 快照留存
```

### 2.3 关键设计决策

1. **单机单进程、SQLite 起步**：不引入 PostgreSQL 与 Docker，降低排障成本，保留演进路径；
2. **MediaMTX 作为演进项**：MVP 由检测 worker 直连视频源，多路模拟与录像阶段再引入；
3. **自训练为主、开源模型作对比基线**：YOLO26n 自训练，D-Fire / gengyanlei yolov5 / Pyronear 作为对比；
4. **前端直接采用 Vue3**：不使用旧的原生 demo 作为正式代码，仅作视觉参考；
5. **演示双通道保底**：手机推流为主，上传视频为辅；
6. **误报控制**：连续多帧 + 置信度阈值 + 告警冷却；
7. **文档先行**：文档产出与开发进度同步，每阶段都有对应交付物；
8. **智能体分级设计（新增）**：本地多尺度检测与时序融合为一级，视觉语言模型只复核高风险/低置信样本，兼顾实时性与准确率；
9. **远距离识别（新增）**：切片推理 + 高分辨率输入 + 小目标/烟类数据训练，并建立远景测试集单独评估；
10. **数据治理（新增）**：先去重、再按相似组划分数据集，避免验证集泄漏；数据版本 v1（原始）→ v1.1（清洗）→ v2（补充 smoke 与远景）。

## 5. 主要风险与应对

| 风险 | 影响 | 应对措施 |
| --- | --- | --- |
| 数据重复与泄漏 | 指标虚高、结论不可信 | 先清洗去重，再按相似组重划分并重训，如实记录指标变化 |
| 远距离数据稀缺 | 无法满足老师新增要求 | 定向查找林火/监控远景数据；切片推理 + 小目标训练；建立远景测试集 |
| 智能体依赖外部模型或网络 | 复核延迟或不可用 | 优先本地小模型量化版本；云端 API 作为可选，复核失败时回退本地规则 |
| 翻拍屏幕检出率不稳定 | 手机演示效果差 | 冒烟阶段用课堂同款素材测试，准备多套素材 |
| 手机热点/推流现场问题 | 重点功能演示失败 | 上传视频保底通道；演示前全链路预演 |
| 每周有效时间不足 | 进度延迟 | 核心闭环优先；每周可演示；后置功能及时降级 |
| 两名成员基础较弱 | 文档/测试质量参差 | 提供模板与清单；强成员 review；任务拆到可执行粒度 |
