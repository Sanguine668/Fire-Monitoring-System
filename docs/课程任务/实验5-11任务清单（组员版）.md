## 二、基本要求与流程

### 2.1 工具要求

| 实验 | 首选工具 | 说明 |
| --- | --- | --- |
| 5 进度、6 成本、7 质量 | **Microsoft Project** | 老师要求首选 Project。5、6 用同一份 `项目任务分解.mpp`；7 在同一份文件上增加质量活动任务与自定义域 |
| 8 配置 | **Git**（Microsoft Project 辅助） | 配置管理软件的主流是版本控制工具；Project 只用来提供"比较基准 + 中期计划"作为基线的辅助证据 |
| 全部 | Word / Markdown | 正文用 Word 交，草稿可用 Markdown 放仓库便于协作与版本管理 |

### 2.2 写作口径

1. **一份实验一份文档**，封面 + 正文，标题层次最多三级；
2. 正文结构对照 `软件项目管理课程文档/PMBOK图解.ppt`：
   - 实验 5 → PMBOK 6.5 制定进度计划、6.6 控制进度；
   - 实验 6 → PMBOK 7.1 估算成本、7.2 制定预算、7.3 控制成本（工具为挣值管理）；
   - 实验 7 → PMBOK 8.1 规划质量、8.2 实施质量保证、8.3 实施质量控制；
   - 实验 8 → PMBOK 4.5 实施整体变更控制；
   - 实验 9 → PMBOK 11.1 ~ 11.6；实验 10 → PMBOK 10.1 ~ 10.5；实验 11 → PMBOK 9.1 ~ 9.4。
3. 每个实验的"实验目的、实验内容"照抄老师下发的原文，不要改写。

### 2.3 数据与事实要求

1. 文档里引用的数据、指标、模块状态**必须能在仓库中找到出处**，不允许编造；
2. 可引用的真实材料：
   - 进度与成本数据 → `docs/课程任务/任务4-工作任务分解说明书/项目任务分解.mpp`；
   - 质量数据 → `docs/课程任务/数据集质量报告/数据质量体检报告.md`、`docs/test-records/` 三份测试记录；
   - 配置数据 → 仓库的提交历史、分支与 PR 记录；
   - 风险素材 → `docs/superpowers/specs/2026-09-09-fireguard-ai-design.md` 第 12 节风险登记；
   - 人员与分工 → `docs/课程任务/任务2-项目章程/`（项目章程）；
   - 沟通与协作事实 → `docs/课程任务/00_任务分工与过程记录.md`、`docs/课程任务/过程记录/`。
3. 涉及项目成果的表述要与实际一致：需求规格说明书已于 2026-09-14 定稿，系统核心闭环已于 09-22 完成，不要再写成"未完成"。

### 2.4 提交流程

1. 每人在自己的分支上工作，提交信息格式：`类型(实验N): 说明 - 姓名`，例如 `docs(实验7): 完成质量管理计划前四章 - 欧阳宇康`；
2. 完成后发起 Pull Request，由组长审核合并，`master` 分支只由组长合并；
3. **`.mpp` 是二进制文件，Git 无法自动合并**：实验 5 与实验 6 共用同一份文件，蔡俊杰先完成实验 5 并提交，李汶航再拉取最新版做实验 6，**两人不要同时修改同一份文件**；
4. 确实操作不了 Git 的成员，把文件与截图打包发组长，由组长代提交并在提交信息中注明原作者。

### 2.5 交付前自查清单

- [ ] 封面信息填写完整（课程名称、实验室 BS329、姓名学号、实验项目名称、日期）；
- [ ] 引用的数据能指出出处，没有编造；
- [ ] 至少 2 类过程证据（截图、记录、日志、数据表）已归档到 `过程记录/<姓名>/`；
- [ ] 文档已由另一名成员交叉检查并留下意见；
- [ ] 格式统一后交陈泽恩排版，再交组长终审。
