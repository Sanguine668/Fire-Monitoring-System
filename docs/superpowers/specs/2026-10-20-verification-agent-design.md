# 告警复核智能体设计（轻量版）

- 项目：火情智能监测与预警系统（FireGuard AI）
- 版本：v1.0（2026-10-20）
- 关联文档：《远距离识别与烟类检测能力升级设计》《需求规格说明书》

## 1. 要解决的问题

单帧目标检测有两个典型问题：

1. **误报**：夕阳、路灯、蒸汽、反光等暖色/白色区域容易被判为火或烟；
2. **远景漏检**：火点只占几十个像素，整图缩放到 640 后特征被稀释。

只靠调高置信度阈值会同时压掉真实告警。系统采用“多级复核”的处理链：先尽量把远景目标找出来，再用局部证据和时序一致性把误报压下去。

## 2. 三层结构

| 层级 | 做什么 | 实现 |
| --- | --- | --- |
| 感知层 | 常规帧整图检测；每 2 秒做一次全图切片扫描 | `detector.detect` / `detector.detect_tiled` |
| 时序层 | 切片结果在两次扫描之间保持，避免烟雾告警因普通帧漏检而断档；烟雾仍需连续多帧确认 | `worker.py` 的 `_tile_objects` + `AlarmEngine` |
| 决策层 | 告警触发时，裁出目标局部区域放大后二次检测；同类置信度不达阈值则抑制本次告警 | `detector.verify_region` + `verifier.py` |

## 3. 局部复核算法

输入：当前帧、触发告警的检测框、告警类别、复核阈值。

1. 以检测框为中心外扩 25% 作为复核区域，边界裁到画面内；
2. 若区域最短边小于 96 像素，等比放大到 96 像素（最多 8 倍），避免退化输入；
3. 用同一模型对局部区域推理，取同类别的最高置信度；
4. 最高置信度不低于 `verify_threshold` 时通过复核，否则视为单帧误报并抑制。

复核只发生在“即将产生告警”的时刻，不增加普通帧的推理开销。

## 4. 参数

| 参数 | 默认 | 范围 | 说明 |
| --- | --- | --- | --- |
| `verify_enabled` | 1 | 0/1 | 是否启用告警二次复核 |
| `verify_threshold` | 0.20 | 0.05~0.90 | 局部复核的最低同类置信度 |
| `tiling_enabled` | 1 | 0/1 | 是否启用周期切片扫描 |
| `tile_size` | 640 | 320~1280 | 瓦片边长 |
| `tile_overlap` | 0.20 | 0~0.50 | 瓦片重叠率 |
| `tile_interval` | 2 | 1~10 秒 | 切片扫描间隔 |

## 5. 为什么先不上 VLM

本地 6GB 显存要同时跑检测与视觉大模型，延迟和显存都吃紧；课堂演示更看重“稳定、可解释、可复现”。本期先用规则驱动的局部复核把误报压下来，VLM 复核保留为后续增强：当本地复核结果处于灰色区间（例如 0.15~0.25）时，再调用云端或本地量化 VLM 做一次语义判断。

这样设计的好处是：即使没有网络或大模型，系统也能独立完成“检测—复核—告警”闭环；接入 VLM 时只需替换决策层，不影响前端与告警链路。

## 6. 验证方式

1. 单元测试：区域裁剪边界、放大逻辑、同类置信度筛选；
2. 集成测试：切片坐标平移与跨片 NMS；
3. 数据评测：在 2,469 张困难负样本上统计误报率，在 520 张远景小目标子集上统计召回；
4. 演示：用 `storage/uploads/demo_farfield.mp4` 对比开启/关闭远距离模式时的检出与告警。

## 7. 风险

- 复核阈值过低会放过误报，过高会压掉真实弱信号，需要按新模型重新校准；
- 切片结果保持时间等于扫描间隔，目标快速消失时可能多保留一帧，属于可接受的延迟；
- 困难负样本来自不同来源，误报率只能作为横向对比，不等价于真实场景的绝对误报率。
